2026-06-14: built a **daily feedback-digest email** so the user actually sees "Not quite right?" reports instead of them sitting unread in the admin queue.

- **`studio/feedback_digest.py`** — pure `build_digest(rows, now)` (testable) + `main()`. Queries `feedback WHERE status='open'`, e-mails operator (prompt / user's words / date / canvas id), splits NEW-in-24h vs older, caps older at 30, **sends nothing when empty**. Surfaces only; never edits/resolves. `tests/test_feedback_digest.py` (5 tests).
- **CDK** (`infra/sevim_stack.py`, block "6d"): Fargate task `python -m studio.feedback_digest` on `scheduler.CfnSchedule` `cron(0 7 * * ? *)` (07:00 UTC daily), **NO EndDate** (ongoing, unlike the Aug-2026-bounded probe). Gated behind **`SEVIM_FEEDBACK_DIGEST_ENABLED`** (off for clones), recipient reuses `SEVIM_PROBE_ALERT_EMAIL`. Mirrors the probe's least-privilege setup (own SG `db.connections.allow_default_port_from`, scheduler role scoped to ecs:RunTask + iam:PassRole, SES send). Flag added to operator `.env`. Commit `17808a9`.

**BUG found while testing (commit `97364aa`, the important one):** running `python -m studio.feedback_digest` (and `python -m studio.quality_probe`) bypasses `studio/__main__.py`, which is the ONLY place that calls `service.secrets.bootstrap()`. bootstrap() assembles `SEVIM_TELEMETRY_DB` (the `postgresql://` RDS URL) from the ECS-injected `SEVIM_DB_SECRET_JSON`. Without it, `sevim.telemetry.get_telemetry()` silently falls back to an **ephemeral per-container SQLite** (`_make_backend` keys on the URL scheme; unset → SQLite default). So every probe/digest task had its own throwaway DB and never touched the real RDS. Fix: call `bootstrap()` at the top of both entrypoints' `main()` before importing/using telemetry. The probe had hidden this because it only READS the answer-cache (empty = silent no-op); the digest exposed it because it depends on the shared feedback table. **Reusable lesson:** any new `python -m studio.<x>` ECS entrypoint MUST call `service.secrets.bootstrap()` first or it gets ephemeral SQLite, not RDS. (`[secrets] sevim/db_url: ClientError — skipping` in logs is BENIGN — that named Secrets-Manager secret doesn't exist; bootstrap then hydrates from SEVIM_DB_SECRET_JSON and the URL comes out `postgresql://sevim:…`.)

**2026-06-14 later — both reports FIXED (commit `fde5565`, deployed).**
- **Newton "these are not tangent lines":** the correct deterministic renderer `studio/templates/newton.py::newton_method` (draws real SymPy-slope tangents from (xₙ,f(xₙ)) to (xₙ₊₁,0)) only fires when the prompt PINS a concrete f/x₀ (template-router extracts them). A VAGUE prompt ("explain Newton's method") supplied none → fell to LLM-SVG → non-tangent lines. (express.py already had a reviewer flag `tangent_without_function_spec` diagnosing this but it only nudged the LLM retry.) Fix: `studio/templates/newton_intro.py` — `is_newton_intro_prompt` matches Newton prompts with NO concrete function (regex `_HAS_FUNCTION` defers `f(x)=`/`x^2`/`sqrt(`/`sin(`… to the template router) and routes them to the canonical √2 example (root of x²−2 from x₀=2) through the SAME exact renderer. Flag `SEVIM_NEWTON_ROUTE`, template id `newton_intro`. ALSO fixed a latent bug in newton.py: narration highlighted iterate LABELS (`xn_i_label`), which the 60px de-collision rule SUPPRESSES for clustered iterates → dangling highlight refs; now highlights the always-drawn dots (`xn_i`).
- **Taylor-sin "didn't highlight curves/legends when mentioning them":** `studio/templates/taylor_sin.py` renders sin(x) + degree-1/3/5/7 Taylor polynomials, each curve id `curve_t{1,3,5,7}`/`curve_sin` + legend id `leg_*`, narration highlights `[curve_tN, leg_tN]` per phrase. Polynomials arithmetic-checked (factorials + improving error). `_clipped_path` splits polylines so diverging polynomials exit the frame instead of leaving the viewBox (probe-safe). Flag `SEVIM_TAYLOR_SIN_ROUTE`, template id `taylor_sin`. NAME-COLLISION GOTCHA: don't name a template module `newton_method.py` — `studio/templates/__init__.py` re-exports a `newton_method` FUNCTION (from newton.py) that shadows the submodule. tests/test_newton_method.py + tests/test_taylor_sin.py; 536 tests pass. These are cascade routes (NOT part of the paper's "nineteen template_router templates" count). Both reports then marked **resolved** in RDS (status='resolved', resolved_sha=fde5565) so the digest stays silent.
